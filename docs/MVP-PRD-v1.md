# Pawtrace 第一版 MVP 产品需求文档

> 文档状态：已确认  
> 版本：v0.2  
> 更新日期：2026-10-08  
> 产品形态：响应式 Web 页面  
> 目标：用最小功能闭环验证宠物主人是否愿意提出健康问题，以及宠物医生是否愿意回答问题、记录病例和参与专业讨论。

## 1. 产品概述

Pawtrace 是面向宠物主人和宠物医生的宠物健康社区。

- 所有注册用户默认拥有宠物主人身份，可以建立宠物档案与宠物病史、发布宠物日常和养宠经验、提出宠物健康问题，并查看医生的回答。
- 用户可以在宠物主人身份基础上申请认证为宠物医生或医生助理。认证后的专业用户仍可使用全部宠物主人功能。
- 宠物医生可以回答公开问题、接收个人提问、维护病例库，并参与学术论坛。
- 医生助理可以维护病例库并参与学术论坛，但不能以宠物医生名义提供正式健康回答。
- 平台管理员负责专业身份认证、内容治理和举报处理。

第一版仅开发响应式 Web 页面，不开发原生 App、微信小程序或桌面客户端。

## 2. MVP 范围原则

第一版优先实现以下两个完整闭环：

```text
宠物主人：手机号登录 → 创建宠物档案 → 发布健康问题 → 医生回答 → 主人追问/标记已解决

专业用户：手机号登录 → 提交医生/医生助理认证 → 创建私密病例 → 匿名发布学术讨论 → 同行评论交流
```

第一版不追求完整在线问诊能力，也不提供诊断、处方、支付和急诊服务。

## 3. 用户角色

### 3.1 游客

- 浏览公开的社区内容和健康问答；不能进入学术论坛。
- 查看公开的用户主页和医生主页。
- 不可发布、评论、点赞或收藏。
- 执行互动操作时进入登录页。

### 3.2 宠物主人（所有注册用户的默认身份）

- 创建和管理自己的宠物档案。
- 发布宠物日常、养宠经验和健康问题。
- 对公开内容点赞、评论和收藏。
- 对自己发布的健康问题进行追问或标记已解决。
- 关注其他用户或认证专业人员，并查看关注内容流。
- 维护自己宠物的病史记录。

### 3.3 医生助理

- 医生助理是附加在宠物主人身份上的认证专业身份。
- 通过相关专业学历材料完成认证。
- 认证通过后，可以创建和管理个人病例库。
- 可以浏览、发布和评论学术论坛内容。
- 不得以宠物医生身份回答健康问题，也不能接收指定医生的个人提问。

### 3.4 宠物医生

- 宠物医生是附加在宠物主人身份上的认证专业身份。
- 需要使用执业兽医资格证完成认证。
- 拥有宠物主人的全部功能。
- 认证通过后，可以用医生身份回答健康问题。
- 可以接收宠物主人向本人发起的个人健康提问。
- 创建和管理自己的私密病例。
- 将病例匿名化后发布到学术论坛。
- 发布学术话题并参与同行讨论。

### 3.5 管理员

- 审核宠物医生和医生助理认证申请。
- 管理用户和公开内容。
- 查看并处理举报。
- 下架违规帖子、问题、回答或评论。

## 4. 账号与登录

### 4.1 登录方式

第一版仅支持中国大陆手机号和短信验证码登录，不提供密码、微信、邮箱或第三方登录。

登录流程：

1. 用户输入 11 位手机号。
2. 点击“获取验证码”。
3. 系统生成 6 位模拟验证码，并在页面提示中直接展示。
4. 用户输入验证码并提交。
5. 新手机号自动注册，老手机号直接登录。
6. 新用户首次登录后完善昵称，系统自动赋予宠物主人身份。

用户无需在注册时选择身份。需要专业功能时，可从个人中心申请认证为“宠物医生”或“医生助理”。同一用户第一版只能持有一种专业身份。

### 4.2 模拟短信规则

- 不连接真实短信服务商，不产生短信费用。
- 验证码为 6 位数字，有效期 5 分钟。
- 同一手机号 60 秒内不能重复获取。
- 每次重新获取后，上一个验证码失效。
- 开发和演示环境在页面展示：“模拟验证码：123456”。
- 后端仍需校验手机号、验证码、有效期和使用状态，避免前端直接跳过验证。
- 模拟验证码不得作为未来生产环境的默认实现。

### 4.3 登录状态

- 登录成功后保持会话。
- 会话失效时返回登录页，登录后尽量回到原页面。
- 用户可以主动退出登录。

## 7. 功能需求

### 7.1 首页与社区内容

首页展示公开内容卡片，支持按“推荐、宠物日常、养宠知识、健康问答”切换。

社区内容字段：

- 内容类型：宠物日常、养宠知识。
- 标题：养宠知识必填，宠物日常可选。
- 正文：必填。
- 媒体：最多 9 张图片，并可另外上传 1 个视频。图片与视频使用两个独立上传分区，不通过同一个混合上传控件选择。
- 关联宠物：可选，仅能选择自己的宠物。
- 标签：可选，最多 5 个。
- 发布时间、作者和互动统计。

互动能力：

- 登录用户可以点赞、取消点赞、收藏、取消收藏、评论和关注作者。
- 作者可以编辑或删除自己的内容。
- 用户可以举报公开内容和评论。
- 第一版不实现转发、私信和复杂推荐算法。

关注系统：

- 登录用户可以关注或取消关注其他前台用户。
- 个人主页显示关注数和粉丝数，并提供关注状态。
- 首页提供“关注”信息流，按发布时间倒序展示已关注用户的公开内容。
- 第一版不提供关注分组、特别关注和关注通知。

首页“推荐”第一版使用简单排序：优先展示近期内容，再参考点赞数和评论数，不做个性化推荐。

媒体基础限制：单张图片不超过 10 MB；单个视频不超过 3 分钟且不超过 100 MB。具体格式白名单在技术设计阶段确定。

### 7.2 宠物档案

宠物主人可以创建多个宠物档案。

必填字段：

- 宠物昵称。
- 宠物类型：猫、狗、其他。
- 性别：公、母、未知。

可选字段：

- 头像。
- 品种。
- 出生日期或年龄描述。
- 当前体重。
- 是否绝育。
- 过敏史。
- 既往疾病。
- 疫苗情况。
- 驱虫情况。
- 备注。

权限规则：

- 完整宠物档案仅主人本人可见。
- 关联到公开帖子或问题时，只展示昵称、头像、类型、品种、性别和年龄等必要信息。
- 删除宠物前需二次确认；已有健康问题时建议改为停用，保留历史关联。

#### 宠物病史

宠物病史属于宠物主人侧的健康记录，与专业用户使用的病例库分开：

- 主人可以为自己的宠物新增、编辑和删除病史记录。
- 字段包括：记录日期、疾病或症状名称、情况描述、就诊医院、接诊医生、检查结果、用药或治疗、附件和备注。
- 支持最多 9 张图片，并可在独立分区另外上传 1 个视频或文件附件；第一版不做检验单自动识别。
- 宠物病史默认仅主人本人可见。
- 发布健康问题时，主人可以主动选择某条病史作为补充资料；未主动选择的病史不得向任何专业用户展示。公开问题所附病史可由认证宠物医生和认证医生助理查看。
- 病史是主人自行记录的信息，不等同于平台医生作出的诊断结论。

### 7.3 健康问答

#### 发布健康问题

主人需要填写：

- 问题标题，必填。
- 关联宠物，必填。
- 症状描述，必填。
- 症状持续时间，必填。
- 媒体：最多 9 张图片，并可另外上传 1 个视频。图片与视频使用两个独立上传分区。
- 精神状态，可选。
- 饮食饮水情况，可选。
- 排泄情况，可选。
- 已采取措施，可选。
- 问题分类，必填。

发布页固定提示：

> 平台内容仅用于健康知识交流，不能替代线下检查、诊断和治疗。如宠物出现呼吸困难、抽搐、中毒、意识异常或持续出血等紧急情况，请立即前往宠物医院。

#### 回答与追问

- 公开发布的问题可由所有人查看。
- 只有认证通过的医生可以发布“医生回答”。
- 问题作者可以在医生回答下追问。
- 回答医生可以继续回复该追问。
- 第一版不开放普通用户对健康问题给出独立医疗回答，普通用户可点赞或收藏。
- 问题作者可以标记一条回答为“有帮助”，并将问题标记为“已解决”。
- 问题状态包括：待回答、已回答、已解决、已关闭。
- 医生回答需要展示认证标识、擅长领域和免责声明。

#### 发布方式

主人发布健康问题时可以选择两种方式：

1. 发布到健康问答论坛：问题公开展示，由任意认证宠物医生回答。
2. 向医生个人提问：从医生公开主页发起，仅提问者和被指定医生可查看及回复，不进入公开信息流。

个人提问规则：

- 只能向认证宠物医生发起，不能向医生助理或未认证用户发起。
- 第一版不收费、不承诺响应时间，也不支持更换接诊医生。
- 提问内容、关联宠物、媒体附件及用户主动附带的病史仅双方可见。
- 医生可以回答或关闭问题；关闭时需选择原因。
- 个人提问仍采用异步问答形式，不属于实时聊天或正式诊疗。

#### 紧急提示

当标题或症状描述命中配置的紧急关键词时，页面展示醒目的线下就医提示。第一版仅做关键词提醒，不声称其能够准确判断病情。

### 7.4 专业身份认证

所有注册用户默认是宠物主人。用户可以选择申请一种附加专业身份：宠物医生或医生助理。

通用字段：

- 真实姓名，必填，仅认证和后台可见。
- 展示名称，必填，公开展示。
- 所属医院或机构，必填。
- 从业年限，必填。
- 擅长领域，必填，可多选。
- 个人简介，可选。
- 申请身份：宠物医生或医生助理，必填。

不同身份的材料要求：

- 宠物医生：必须上传有效的执业兽医资格证材料。
- 医生助理：必须上传兽医、动物医学等相关专业的学历证明材料。
- 证明材料仅申请人和管理员可见。

认证状态：未提交、审核中、已通过、已驳回。

- 审核中不可重复提交。
- 被驳回后显示原因，允许修改后重新提交。
- 认证通过后，根据类型显示“认证宠物医生”或“认证医生助理”标识。
- 第一版由管理员人工审核。
- 认证身份决定专业权限；用户不能通过前端自行切换或伪造专业身份。
- 如需从医生助理升级为宠物医生，需要提交新的宠物医生认证申请并重新审核。

### 7.5 个人病例库

病例库只向认证宠物医生和认证医生助理开放，未认证用户不能使用。病例默认私密，仅创建者本人可以查看和编辑。

病例字段：

- 病例标题，必填。
- 动物类型、品种、性别、年龄，必填。
- 主诉，必填。
- 病史，可选。
- 体格检查，可选。
- 辅助检查，可选。
- 初步判断，可选。
- 诊疗方案，可选。
- 随访与结果，可选。
- 病例标签，可选。
- 媒体或附件，可选，支持图片及视频。
- 病例状态：草稿、诊疗中、已结案。
- 可见性：私密、已发布为匿名讨论。

第一版暂不提供病例模板、结构化检验单识别、协作编辑和医院系统导入。

### 7.6 学术论坛

- 学术论坛整体仅认证宠物医生和认证医生助理可进入和查看。
- 两种认证身份都可以发布学术话题、病例讨论和评论回复。
- 帖子类型：病例讨论、诊疗经验、学术问题。
- 支持标题、正文、图片或视频、标签和评论。
- 医生可以从个人病例创建讨论，系统复制允许公开的字段，不直接公开原私密病例。
- 发布前必须确认内容已匿名化，不包含主人姓名、手机号、详细住址、病例编号等个人信息。
- 作者可以编辑或删除自己的讨论。

第一版使用论坛式异步交流，不开发实时聊天室。

### 7.7 通知

第一版提供站内通知，不提供短信、邮件和系统推送。

通知类型：

- 健康问题收到医生回答。
- 医生收到新的个人提问。
- 医生回答收到主人追问。
- 帖子或讨论收到评论。
- 内容被点赞或收藏。
- 专业身份认证通过或驳回。
- 举报处理结果。

通知支持未读标记、全部已读和跳转到相关内容。

### 7.8 搜索与筛选

- 普通用户可搜索社区帖子和公开健康问题的标题及正文。
- 认证宠物医生和认证医生助理可额外搜索学术讨论。
- 可按内容类型、宠物类型、问题分类、学术标签筛选。
- 第一版不搜索私密病例、手机号或认证材料。
- 第一版使用数据库查询，不引入独立搜索服务。

### 7.9 管理后台

管理员使用预置后台账号登录，不与前台手机号登录共用入口。

后台能力：

- 查看宠物医生及医生助理认证列表和详情。
- 通过或驳回认证，并填写驳回原因。
- 按类型、状态和时间筛选公开内容。
- 下架或恢复帖子、问题、回答和评论。
- 查看举报详情并标记处理结果。
- 禁用或恢复用户账号。

所有管理员操作需要保留操作人、时间、对象和原因。

## 9. 内容状态

### 9.1 通用公开内容

- 草稿：仅作者可见。
- 已发布：公开可见。
- 已下架：作者可见下架原因，其他用户不可见。
- 已删除：逻辑删除，前台不可见。

### 9.2 健康问题

```text
待回答 → 已回答 → 已解决
   └────────────→ 已关闭
```

### 9.3 专业身份认证

```text
未提交 → 审核中 → 已通过
                 └→ 已驳回 → 修改后重新提交
```

## 11. 页面设计原则

- 桌面端和移动端浏览器均可使用，优先保证手机宽度下的核心流程。
- 普通用户主导航突出：首页、健康问答、发布、通知、我的。
- 认证宠物医生和医生助理登录后增加明显的“专业工作台”入口；仅宠物医生显示待回答和个人提问入口。
- 整体视觉偏专业医疗风格，以清晰、可信、克制为主要原则，宠物元素仅作为适度点缀。
- 医疗相关页面避免娱乐化表达，也避免营造已经完成诊断的误导。
- 所有列表具备加载中、空状态、请求失败和无权限状态。
- 表单离开前如有未保存内容，需要二次确认。
- 图片和视频上传需展示进度、失败重试、预览和删除能力。

## 12. 非功能要求

### 12.1 安全与隐私

- 手机号、认证材料和私密病例不能通过公开接口访问。
- 后端执行身份和资源归属校验，不能只依赖前端隐藏按钮。
- 用户上传文件限制类型和大小，文件名使用系统生成值。
- 日志中不输出完整手机号、验证码或认证材料地址。
- 删除操作默认使用逻辑删除。

### 12.2 性能

- 列表统一分页，第一版默认每页 20 条。
- 图片生成缩略图或使用适当尺寸，视频使用封面图，避免首页直接加载原始媒体文件。
- 常规页面在本地开发环境下应在可接受时间内完成首屏加载。

### 12.3 兼容性

- 支持最新版 Chrome、Edge、Safari。
- 移动端支持常见 Android 浏览器和 iOS Safari。
- 第一版不承诺兼容 IE。

## 13. 当前技术约束

沿用仓库已有技术结构：

- 前端：React + TypeScript + Vite。
- 后端：Node.js + Express + TypeScript。
- 数据访问：Prisma。
- 数据库：MySQL。
- 部署：Docker Compose + Nginx。

第一版图片和视频可以使用本地开发存储，但文件访问层应保留未来切换对象存储的空间。

## 14. 明确不在第一版范围内

- 原生 App 和微信小程序。
- 真实短信发送。
- 实时聊天室和私信。
- 音视频问诊。
- 在线支付、订单和退款。
- 电子处方、药品销售和自动用药建议。
- AI 自动诊断。
- 医院信息系统或智能硬件接入。
- 个性化推荐算法。
- 关注分组、特别关注和复杂社交关系推荐。
- 多语言和国际手机号。
- 复杂运营活动、会员和积分体系。

## 15. MVP 验收场景

### 场景 A：手机号登录

1. 新用户输入合法手机号并获取模拟验证码。
2. 页面显示验证码，用户填写后登录成功。
3. 用户填写昵称，系统默认赋予宠物主人身份。
4. 再次访问时可以保持登录状态并正常退出。

### 场景 B：主人提出健康问题

1. 主人创建一只宠物。
2. 主人选择该宠物并提交包含文字及图片或视频的健康问题。
3. 问题出现在健康问答列表，状态为“待回答”。
4. 非认证用户无法发布医生回答。

### 场景 C：主人向医生个人提问

1. 主人进入认证宠物医生的个人主页并发起提问。
2. 该问题不出现在公开问答列表，只有双方可以查看。
3. 被指定医生收到站内通知并进行回答。
4. 医生助理不能被选择为个人提问对象。

### 场景 D：医生回答公开问题

1. 医生提交认证，管理员审核通过。
2. 医生从工作台进入待回答问题并提交回答。
3. 主人收到站内通知并进行追问。
4. 医生回复追问，主人将问题标记为已解决。

### 场景 E：专业身份、病例与学术讨论

1. 用户分别可用执业兽医资格证或相关学历材料申请宠物医生或医生助理认证。
2. 未认证用户不能进入病例库或学术论坛。
3. 认证医生或医生助理创建私密病例并保存。
4. 其他用户无法访问该病例。
5. 创建者从病例生成匿名学术讨论。
6. 其他认证医生或医生助理可以评论和回复。

### 场景 F：社区、关注与治理

1. 用户发布宠物日常或养宠经验。
2. 其他登录用户可以点赞、评论、收藏和举报。
3. 用户关注作者后，可以在关注信息流看到作者的新公开内容。
4. 管理员处理举报并下架内容。
5. 内容作者可以看到下架状态和原因。

### 场景 G：宠物病史

1. 主人为自己的宠物添加一条病史记录。
2. 其他普通用户和专业用户默认无法查看。
3. 主人发布健康问题时主动选择附带该病史。
4. 公开问题所附病史只有问题作者、认证宠物医生和认证医生助理可以查看；普通浏览者不可见。

## 16. 建议开发顺序

1. 建立默认宠物主人身份、手机号模拟验证码和会话体系。
2. 完成个人资料、宠物档案、宠物病史和媒体上传。
3. 完成公开健康问题、个人提问、医生回答、追问和状态流转。
4. 完成医生/医生助理认证和管理后台审核。
5. 完成专业病例库和仅限认证专业用户的学术论坛。
6. 完成社区帖子、评论、点赞、收藏、关注和举报。
7. 完成通知、搜索、响应式适配和整体联调。

## 17. 已确认的产品决策

1. 所有注册用户默认是宠物主人，认证专业身份后仍保留全部宠物主人功能。
2. 专业身份分为宠物医生和医生助理；宠物医生验证执业兽医资格证，医生助理验证相关专业学历。
3. 宠物病史属于主人侧功能；专业病例库仅认证宠物医生和医生助理可使用。
4. 健康问题既可以发布到公开问答论坛，也可以向指定认证宠物医生私密提问。
5. 第一版包含关注和粉丝关系，并提供简单的关注信息流。
6. 社区帖子和健康问题支持最多 9 张图片，并可另外上传 1 个视频；图片和视频在页面中分区上传与展示。
7. 学术论坛仅认证宠物医生和认证医生助理可访问及互动。
8. 管理后台第一版不做复杂数据统计。
9. 页面整体采用偏专业医疗的视觉方向。

当前权限假设：医生助理可以使用病例库和学术论坛，但不能发布正式医生回答，也不能接收个人健康提问。若产品规则需要开放其中某项能力，应在交互设计前调整权限矩阵。
