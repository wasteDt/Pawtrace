# Pawtrace 管理后台规划 v1

## 1. 规划目标

管理后台不是单一的认证审核页面，而是平台治理入口。第一版先建立稳定的信息架构和导航框架，再按业务阶段逐步开放模块，避免后续把用户、内容、举报和日志继续堆在认证页面中。

核心原则：

- 管理员与前台用户使用完全独立的登录、Session 和权限体系。
- 审核申请与管理已认证身份是两个不同模块。
- 通过、驳回、撤销、恢复等高风险操作必须填写原因、二次确认、写入审计日志并通知用户。
- 管理员默认不能查看宠物病史、个人提问、私密病例正文等非治理必需数据。
- 后台导航允许模块逐步上线；未实现模块显示“规划中”，不伪造数据。

## 2. 后台整体信息架构

```text
管理后台
├─ 工作台
│  ├─ 待办数量
│  ├─ 今日处理概览
│  └─ 风险与异常提醒
├─ 身份认证
│  ├─ 认证申请
│  └─ 已认证人员
├─ 用户管理
│  ├─ 用户列表
│  └─ 用户详情
├─ 内容治理
│  ├─ 社区内容
│  ├─ 健康问答
│  └─ 学术论坛
├─ 举报中心
│  ├─ 待处理举报
│  └─ 举报记录
├─ 运营管理
│  ├─ 公告与系统消息
│  └─ 内容分类与标签
├─ 审计日志
└─ 系统设置
   ├─ 管理员与角色
   └─ 平台规则
```

桌面端采用固定侧边导航；顶部栏放置当前页面标题、全局搜索入口、管理员身份和退出按钮。窄屏时侧边导航折叠为抽屉。

## 3. 模块功能边界

### 3.1 工作台

工作台只提供治理摘要和快捷入口，不在第一版实现复杂经营统计。

- 待审核专业认证数量。
- 待处理举报数量。
- 今日新增用户、内容和问题数量。
- 最近管理操作。
- 快捷进入下一条待审核申请。

### 3.2 身份认证：认证申请

用于处理一次申请，不承担已认证人员的日常管理。

- 按待审核、已通过、已驳回、已撤销筛选。
- 按申请类型、提交时间和关键词筛选。
- 查看申请资料和私密证明材料。
- 使用常用理由或自定义理由驳回。
- 审核通过后立即生成或更新专业身份。
- 展示审核人、审核时间、审核备注和申请历史。

### 3.3 身份认证：已认证人员

新增独立列表，用于管理已经生效的宠物医生和医生助理。

- 查看当前认证类型、公开名称、机构、擅长领域、认证时间和当前状态。
- 查看该用户的全部认证申请与身份变更记录。
- 撤销专业身份。
- 恢复被误撤销的专业身份，仅作为纠错操作。
- 从医生助理升级为宠物医生仍必须通过新的宠物医生申请，管理员不能直接修改身份类型。

#### 撤销身份规则

1. 只能对 `APPROVED` 身份执行。
2. 必须选择常用原因或填写自定义原因，原因对用户可见。
3. 必须二次确认，确认文案明确说明权限将立即失效。
4. 事务内将专业档案改为 `REVOKED`、记录撤销时间、取消该用户仍在审核中的升级申请、写入审计日志并创建用户通知。
5. 用户仍保留宠物主人身份和所有宠物主人功能。
6. 用户立即失去病例库、学术论坛、医生回答和接收个人提问等专业权限。
7. 已发布内容不删除；历史内容继续保留原作者信息，但认证标识显示为“认证已撤销”，且不能继续执行专业操作。
8. 用户可以重新提交认证申请。

#### 恢复身份规则

- 仅用于管理员误操作纠正，不替代重新认证流程。
- 必须填写恢复原因并二次确认。
- 恢复原专业身份类型，不允许借恢复操作改变类型。
- 写入审计日志并通知用户。
- 后续引入角色权限后，仅高级管理员可以执行恢复。

### 3.4 用户管理

- 以昵称、用户 ID、脱敏手机号搜索。
- 查看账号状态、注册时间、专业身份摘要和公开内容摘要。
- 禁用或恢复账号，并填写原因。
- 不在用户详情直接展示宠物病史、私密病例或个人提问正文。

### 3.5 内容治理

- 管理日常动态、养宠知识、健康问答和学术讨论。
- 查看内容状态、作者、发布时间、举报数量和公开媒体。
- 下架、恢复或标记需要复核。
- 私密问题和私密医疗内容仅在合法举报流程需要时按最小范围开放。

### 3.6 举报中心

- 统一承接用户、内容、评论和回答举报。
- 状态为待处理、处理中、已处理、已驳回。
- 处理决定必须关联处理人、原因和处置动作。

### 3.7 运营管理

- 发布平台公告和系统通知。
- 管理内容分类、专业方向和社区标签。
- 第一版不加入复杂推荐配置和数据看板。

### 3.8 审计日志

- 记录管理员、时间、动作、对象、原因和必要的变更摘要。
- 支持按管理员、动作类型、对象和时间筛选。
- 审计日志不可由普通管理员删除或修改。
- 日志不得记录密码、Session、完整手机号、证明文件地址和私密医疗正文。

## 4. 管理员角色规划

当前开发环境可继续使用单一管理员，数据结构和导航按以下角色预留：

| 角色 | 主要权限 |
| --- | --- |
| 超级管理员 | 管理员账号、角色、全部治理操作、恢复被撤销身份 |
| 认证审核员 | 审核申请、查看认证材料、撤销身份 |
| 内容审核员 | 内容治理、举报处理 |
| 客服支持 | 查看有限用户摘要和处理状态，不查看认证材料 |

后台接口必须服务端鉴权，不能只靠前端隐藏菜单。

## 6. 关键状态流

### 6.1 申请状态

```text
PENDING ──通过──> APPROVED
   ├────驳回──> REJECTED
   └──用户撤销──> CANCELLED
```

申请审核完成后不可直接改写原结果；如发生管理纠错，应记录新的管理动作，不能篡改历史审核记录。

### 6.2 专业身份状态

```text
APPROVED ──管理员撤销──> REVOKED
REVOKED ──纠错恢复────> APPROVED
REVOKED ──重新申请并通过> APPROVED
```

申请状态和身份状态必须分离：撤销身份不会把历史申请改成驳回，历史申请仍然反映当时的审核结果。

## 7. 第一阶段实施范围

本轮建议直接落实以下内容：

1. 将管理端改为“侧边导航 + 顶部栏 + 内容区域”的后台框架。
2. 新增基础工作台。
3. 将现有审核页面迁移到“身份认证 / 认证申请”。
4. 新增“已认证人员”列表和详情。
5. 实现身份撤销、恢复、用户通知和审计日志。
6. 新增审计日志列表。
7. 用户、内容、举报、运营和设置先提供清晰的规划中页面。

## 8. 验收标准

- 管理员登录后首先进入后台工作台，而不是直接进入审核列表。
- 任意后台页面均能看到统一导航，刷新后保持正确页面。
- 认证申请和已认证人员分属不同菜单。
- 管理员可以撤销有效专业身份，用户无需刷新即可收到通知且权限立即失效。
- 管理员可以纠正误撤销，恢复操作有独立原因、通知和审计记录。
- 管理员不能直接把医生助理改为宠物医生。
- 每次审核、撤销和恢复都能在审计日志中查询。
- 规划中模块不会展示虚假统计或可点击的无效操作。
